# 海克斯标题与图标切片回放

目前仓库没有已标注的实局片段。每个片段单独放在一个子目录，包含无损 PNG 切片和一个 `manifest.json`。建议至少录制：

- 普通走位或弹窗关闭后的背景，无预期更新。
- 从普通画面到首次三选一，再保留几帧静止卡牌。
- 从静止三选一到鼠标悬停、单卡翻牌（包括粒子）和新卡稳定。一次片段可包含多次重掷。

保持无边框窗口并让游戏处于前台。每次抓屏从同一个画面裁出六张切片：三个灰度 2× 上采样标题和三个原尺寸彩色图标区域。图标框按仓库示例画面设置，请用实局 PNG 核对是否完整包含图案。录制时停止助手识别，避免悬浮推荐盖住图标。

```powershell
.\.venv\Scripts\python.exe tests/test_replay_dataset.py --record tests/replay_samples/mayhem-01 --hero 探险家 --seconds 12 --interval-ms 45
```

命令有 3 秒切回游戏的时间。窗口改变或离开前台会结束已开始的片段。索引从 0 递增，例如 `00000_hex_1.png` 对应 `00000_hex_1_icon.png`，其余两张卡按同样规则命名。同一索引使用一个 `frame_ms` 时间戳。脚本按实际采样时间填写，PNG 编码和写入也可能影响录制间隔。

根据 PNG 标注 `manifest.pending.json`，完成后改名为 `manifest.json`。以下为结构示例，实际录制会有更多帧，卡名必须使用项目数据库中的准确名称。

```json
{
  "schema": 2,
  "hero": "探险家",
  "opening": true,
  "frame_ms": [0, 45, 90, 135, 180, 225, 270, 315, 360],
  "events": [
    {
      "type": "popup", "start_ms": 45, "end_ms": 180,
      "cards": {"hex_1": "卡名甲", "hex_2": "卡名乙", "hex_3": "卡名丙"}
    },
    {
      "type": "reroll", "start_ms": 225, "end_ms": 360,
      "cards": {"hex_2": "新卡名"}
    }
  ]
}
```

- `schema: 2` 要求每帧六张 PNG。`schema: 1` 的旧标题片段仍可回放。当前检测器仅使用标题，图标切片用于后续匹配实验。
- `opening` 仅对模拟进入对局后的片段启用。从已打开的三选一开始录制时，也需要为初始全量识别标注 `popup`。
- 每个预期窗口使用闭区间，按时间排序、互不重叠，包含至少一个样本帧。从切片中首次可确认的弹窗或翻牌变化开始，截止到预先确定的允许确认时限。悬停和背景不应标成事件。
- 同一数据集对比参数时，固定采样、事件窗口、游戏版本、OCR 模型和数据库。录制的时间轴不包含回放机器上的 OCR 等待，也不模拟生产调度。

```powershell
.\.venv\Scripts\python.exe tests/test_replay_dataset.py tests/replay_samples
```

误触发率 = 预期窗口外输出 UPDATE 的帧数 ÷ 窗口外总帧数。漏检率 = 窗口内未正确识别的预期事件数 ÷ 预期事件总数。窗口内错卡、错误类型或重复更新另行计数；出现其中任一错误时返回 1。无分母显示 N/A，显式指定空数据集返回 2。单卡确认延迟以录制时间轴计算，单卡 OCR 与重新排序耗时以回放机器实测计算，包含重试调用，二者分别报告 P50 和 P95。
